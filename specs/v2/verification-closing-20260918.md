## 实现

- Bash 验证记录区分实际失败、未运行、无有效报告、超时。目标文件不存在时保留规范化工作目录与目标路径，不执行命令。报告无效但进程非零退出时，不豁免实际失败。
- 后续同类别、同目录、覆盖原目标且仍然有效的通过记录，可以替代“未运行／无有效报告”。保留旧记录和替代调用 ID；不同命令的真实断言失败不能被别处的通过结果覆盖，替代检查后来失败也会撤销替代关系。
- 工程任务结束时，即使测试全绿，也在原 Agent Loop 做一次需求与断言复核。复核提示包含可见用户要求、失败、缺失项与已有覆盖，要求检查边界、异常和不变量，按需要补测修复。单次标记从持久历史读取，压缩或恢复不重置次数；新用户请求重新计数。没有新增 Agent、重试或恢复框架。
- `bash.verification_report` 的 `checks[].requirements` 记录实际断言覆盖描述。源文件／测试脚本指纹失效后，对应证据失效。工程任务缺少有效覆盖记录时不再标记为 `completed_verified`。这不是需求语义证明，不能保证描述真实或完整。
- UI 展示执行问题、替代记录与“报告声明的断言覆盖”；保留“所列检查已通过，范围见验证记录”的保守总状态。模型口头完成不会改变宿主状态。最终自然语言仍由模型生成，不保证消除所有夸大表述。
- 套件式成功记录也能清零连续 shell 失败计数。没有把 README 变成通用要求。

## 旧比赛记录只读回放

使用保存的真实工具记录与现存目标文件指纹，不调用模型，不修改交付物。整体快照使用历史记录，故这是判定逻辑回放，不是新的端到端验收。

- CSV hard 16K：原 `failed` → `completed_unverified`。单独内联脚本的解析失败被后续同范围有效检查替代；旧记录没有覆盖描述，故不直接升为全部验证通过。
- CSV soft 16K：仍 `failed`。其中一条是复合 shell 命令，无法仅从内联解析诊断证明其他命令没有失败，保守保留，需针对原失败重新验证。旧的预检错误缺少规范目录，也不自动猜测修复范围；新调用已改善记录。
- CSV soft 2K：原 `completed_verified` → `completed_unverified`，缺少有效需求覆盖记录。不能把这项状态变化解释为已修复空字段往返缺陷。
