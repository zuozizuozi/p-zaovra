# C 第二轮：修复实测暴露的问题

状态：代码与本地验证完成；随后已执行独立注册的四项真实回归，消耗 1,639,300 Token，C 尚不能收尾，见 [第二轮实测](./experiments/verification-c2-live-20260918.md)。本文件下述本地验证阶段未调用真实模型。上一轮冻结实验停在 3/4 项，未混入新版统计。B 仍为待办。

## 1. 执行归因与检查关联

- 工具参数校验失败携带结构化输入拒绝标记，沿现有工具结算、事件、会话投影保存。它属于未执行，不是产品断言失败；历史记录同时兼容宿主生成的 `Invalid tool input:` 诊断。
- 验证命令必须有一个可归因的退出状态。复合命令、管道、重定向和裸 JSON 报告在执行前拒绝，保存工作目录与目标范围，并提示拆成独立命令或使用会传播失败的脚本。普通非验证 shell 行为不变。
- 输入拒绝、未运行以及退出 0 但旧格式报告无效，不消耗“已执行 shell 连续失败”计数；实际非零退出、超时与其他执行错误仍计数。现有 provider-turn 和重复调用保护保留，没有增加重试框架。
- `verification_replaces` 可指定此前检查的调用 ID。宿主要求新证据有效、类别相同、目录相同、覆盖原目标。真实断言失败还要求原断言文件指纹完整且不变；不能通过自述“已修复”或无关通过结果清除。
- 无效报告／未执行重试不能覆盖同命令之前的真实失败。旧复合命令缺少可靠阶段信息时不做自动免责，也不修改历史记录为成功。

## 2. 普通命令即可提交覆盖证据

现有 `bash` 增加参数，仍通过原工具注册与执行链路：

```json
{
  "command": "npm test",
  "verification": "test",
  "verification_targets": ["src/csv.js", "test/csv.test.js"],
  "verification_assertions": ["test/csv.test.js"],
  "verification_requirements": ["字段内容包含开头 BOM 时仍能往返保留"]
}
```

普通测试输出直接保留；宿主记录真实退出状态、源码／测试指纹与覆盖说明。无需另写一个只输出 JSON 的报告程序。旧 `verification_report` 保留兼容，但说明和错误反馈优先引导普通命令路径。覆盖说明仍是模型声明，不是语义证明。

## 3. 失败断言不能靠修改期望值自动消失

- 检查记录新增断言文件指纹。显式声明断言文件，同时发现常规 `test`、`tests`、`__tests__`、`fixtures` 目录里的文件；自定义位置应显式提供，不能保证发现任意测试框架的全部输入。
- 观察到实际失败后保留对应断言指纹。后续修改／删除这些文件，即使同一命令 exit 0，也标记“原要求未重新验证”。换命令、省略断言列表或只修改状态文字不能清除这项缺失证据。
- 复原原断言并修复实现、重新通过，可以正常验证；新增测试可放新文件。合法修改原测试同样会触发待复核，这是保守边界，不是自动证明修改恶意或不合理。
- 宿主评估从当前用户请求的持久会话记录读证据，避免模型上下文压缩丢掉失败事实。模型上下文压缩／摘要规则没有重做，B 未推进。
- 收尾复核后每个模型请求附带当前未解决检查和缺失证据；保持系统前缀不变，不新增自动复核次数。宿主状态仍是独立证据来源，不能保证模型自然语言绝无夸大。

## 验证

- 六个相关测试文件共 203 项通过，0 失败，768 次断言；包含真实工具输入拒绝持久化、相对目标路径按会话工作目录归一化的回归。五个包 Core、Schema、Client、SDK JS、App UI 类型检查通过。
- 真正启动本地测试进程的反例：原实现丢 BOM → 实际断言失败；改期望值 → 命令通过但宿主未验证；还原断言、修源码 → 宿主验证通过。没有调用模型。
- 输入拒绝未启动进程；复合命令在执行前拒绝；普通 stdout 携带覆盖记录；无关／改断言的新命令不能清除真实失败；原断言不变的显式重新验证可以消除。
- 会话集成测试验证输入拒绝标记持久化；压缩后仍能读取原请求证据，并给模型最新核对结果，不重复触发收尾复核。
- Client 和 SDK JS 已用各自生成脚本同步，未手改生成文件。

只读回放原始三个实测样本：第二份 CSV 修改失败断言被检测，明确产生 `Failed assertion changed or unavailable; original requirement not reverified`。旧复合命令与旧停止状态仍保守保留，不把历史失败凭空改为成功；第一份 CSV 的检查脚本修改也会触发保守复核。

可复现回放：从 `packages/core` 运行 `bun run script/verification-replay-local.ts <原实验记录目录>`。脚本只读取上下文与文件指纹，不执行提交物命令、不请求模型。
