## 已证实的优化与新修复

### 请求前缀

B 组 **31 次**真实请求的 systemHash 只有 1 个、toolsHash 只有 1 个。相邻请求中，已有消息摘要前缀完整保留，包括验收失败和成功之后的请求。日志保留 requestTraceID、contextEpoch 和规范化用量；没有记录密钥或正文。

B 全程已报告输入缓存比约 **93.6%**（1,209,088 / (83,009 + 1,209,088)）。这是该组的观测，不是相对 A 的因果提升百分比；两组行为、长度、完成程度不同，不以比率冒充成本 A/B 结论。

### Windows 输出丢失

B 环境探索中，目录对象查询多次只返回空白或进度 XML，而 `cmd /c dir` 可以显示文件。这不能全归因于模型。

离线复现：运行包含 `Name=TABLE_OUTPUT_SENTINEL` 的 PowerShell 对象，原实现 stdout 仅有换行。根因是包装脚本显式退出前没有完成 PowerShell 延迟表格格式化；EncodedCommand 还带入了 XML 格式的额外流输出。

参考 [Codex PowerShell 直接传参实现](https://github.com/openai/codex/blob/main/codex-rs/shell-command/src/powershell.rs) 和 [Microsoft Out-Default 文档](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/out-default)，改为直接传一个 `-Command` 参数，使用标准 Out-Default 在退出前刷新输出，并在格式化前保存命令失败状态；关闭无业务意义的进度显示。没有新增 XML 清洗器或模型专属分支。

验证覆盖表格输出、警告/错误保留、非终止错误、throw、原生命令退出 7、显式退出 9、中文与引号、超时子进程清理。Core 相关 **171 项**及 Bash 工具/运行时 **16 项**通过，类型检查通过；上一阶段 LLM **36 项**通过。新 Shell 修复在任务结束后构建并加载，不追加计费任务证明效果。

## 仍未解决，下一步优先级

1. **不完整工具参数的可诊断性与恢复**：两次原始参数都未闭合。尚不能仅靠现有记录区分网关输出限制、流截断和模型格式错误。先保留原始 finish_reason、用量和限制证据，再参考竞品做受限纠正；不能自动拼 JSON 或盲目重放写入。
2. **验收套件与完成状态的契约**：一个套件含多个检查，当前单一分类不足以表达，而模型没有按要求正确登记。应先对齐套件报告、目标文件、失败覆盖与 UI 缺项提示，再考虑支持一次执行记录多个检查；不能把任意 test=0 都等同于全部需求通过。
3. **无必要的重复动作与预算**：B 在环境探索上用了多轮；验收通过后又多次重跑。固定提示没有可靠抑制这些行为。需要会话级预算提示/安全边界控制，以及明确“哪些变更要求重验”的证据；不要删历史或少测功能来达标。外部测试执行者也需要在下一次 provider 请求前管理预算，不能只事后看总数。

本轮不引入激进摘要、经济阈值压缩、自动模型切换、额外 reviewer 或新的批处理框架。
