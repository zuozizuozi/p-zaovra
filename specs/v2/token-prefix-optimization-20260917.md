## 参考与取舍

- [DeepSeek Context Caching](https://api-docs.deepseek.com/guides/kv_cache/)：缓存依赖相同前缀，且是尽力而为。固定不必要变化的前缀，不承诺所有请求命中；本项目使用第三方兼容网关，仍需实测网关行为。
- [Cline act 提示](https://github.com/cline/cline/blob/main/sdk/packages/shared/src/prompt/system/act.ts)：借鉴同轮请求多个独立工具、等待依赖结果、完成前验证。沿用现有工具执行器，不引入批处理框架，也不并发执行相互冲突的写入。
- [OpenCode 会话提示实现](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/prompt.ts)：继续沿用会话历史和现有工具结果通路，不新增第二套任务状态。
- Context Mode 的原始证据外置、按需读取思想已由 Evidence 支持；本轮不增加自动摘要、FTS5、激进压缩或经济阈值压缩。现有材料不足以证明进一步缩减模型可见信息不会影响交付。

## 已完成三步

1. **最小观测**：一次模型请求产生 requestTraceID，继承 sessionID、step、contextEpoch；HTTP 请求最终序列化后，在 Debug 日志记录正文、系统段、工具列表和逐条消息摘要及字节数。不开 Debug 时不计算这些摘要。结束事件记录规范化用量与允许列表中的提供商数字字段。不记录密钥、提示正文或代码，不新建遥测数据库。已有请求执行器记录的重试和响应请求 ID 可以按同一关联字段追踪。缺失提供商用量仍是未知，不能当作免费；日志不是供应商账单。
2. **稳定前缀**：删除每轮放在系统提示中的动态验收记录 JSON，保留固定验收规则；有效 bash 验收元数据随对应工具结果进入原来的历史位置。保留原始输出、失败退出码、目标和日志引用。工具声明按名称稳定排序，权限过滤仍优先，不能为了缓存继续暴露禁用工具。
3. **减少可避免往返**：增加固定指导，鼓励同轮请求独立读取或检查；依赖操作等待结果；失败先定位原因；只有相关文件与环境未变化时才复用证据，变化影响的检查必须重跑。未降低验收要求，未改失败状态推导、重试上限、上下文窗口或模型路由。

普通验证变化不再修改早期系统段，但模型/代理/权限变化、上下文压缩、异常恢复指令仍可能合法改变请求。这里不保证所有历史永远只追加。

## 第四步：同任务真实 A/B

在两个隔离的新目录、新会话，使用同一服务商、模型、权限、提示与验收标准，分别运行修改前和修改后版本。不读取另一组生成结果。记录版本差异、开始结束时间、请求轮次、各类用量、缓存比例、重试与失败、人工提示次数、完整交付质量；新会话缓存键按生产逻辑不同，不为测试强制共享缓存。

基准任务：

> 在当前项目目录从零制作一个可直接打开的浏览器贪吃蛇游戏，不使用外部网络资源。支持方向键与 WASD，禁止直接反向移动；有开始、暂停/继续、结束后重新开始、分数与最高分。失焦自动暂停。布局适合桌面与窄屏。提供简短操作说明。你自己编写并运行可重复的语法、浏览器启动与交互验收，覆盖移动、吃食物计分、碰撞结束、暂停期间不移动、重开重置、失焦暂停及控制台错误；无法验证的项目明确说明。不要通过修改预期结果掩盖失败。最终报告文件入口、实际验收结果和未完成项。

验收先看两组是否满足相同要求，再比较消耗。外部检查只验证与反馈，不代写成品；反馈和追加消耗单独记录。保留模型自主完成结果与人工引导后结果的区别。

第一对样本只能给趋势，不能给稳定节省百分比。提供商限流、服务失败、遗漏用量、缓存时效等异常单独标注，不能把它们强行归因到本次优化。预算将近时评估收尾所需，不为数字好看强制截断运行任务。
