## 修改

1. 失败断言的冻结有解除边界：同类别、同目录、同命令（或显式重新验证）实际通过原始断言版本，且执行前后目标指纹有效后，解除该失败版本的保护。随后追加测试不再被永久拦截。修复前改期望仍不允许；失败命令会明确提示先保留原测试修实现、原样复验，再补测，或把新测试放另一文件。历史版本未能证实通过时仍保守处理。
2. 工具参数纠错按连续失败计算，读取持久会话记录。一个完整成功工具回合可以结束上一纠错阶段；带错误参数回合里的有效兄弟调用不能重置，单纯文字也不能重置。连续两次拒绝仍失败退出，已有重复工具和 provider-turn 限制仍在，不加入无限重试。
3. 新增唯一注册链路内的 `verification_review` 工具。它不执行模型循环或测试，只记录用户原始条款编号、实际检查调用 ID、逐项已验证／未验证及剩余范围。宿主在收尾复核后要求每项条款唯一覆盖，检查证据存在、通过、文件仍新鲜；遗漏、过期证据、任意声明未验证项均使结果保持未验证。拒绝把一条泛化 coverage 字符串当作整个任务完成。
4. 普通验证不再强制重复填写可从常规测试目录发现的断言文件；自定义路径仍需声明。保留源码目标要求及旧 JSON 报告兼容，不把提示文字拼进旧报告 JSON。

原始条款按句号、分号、换行切分以提供稳定引用，不声称这是语义理解。工具会提供原文，模型负责给出覆盖说明；宿主校验记录与真实检查之间的关系，不会自动证明测试断言足以覆盖全部语义。模型如果隐瞒或误解要求，仍可能提交错误覆盖声明，这是明确的剩余边界。既不扫描自然语言关键词冒充语义裁判，也不默默改写用户要求。
