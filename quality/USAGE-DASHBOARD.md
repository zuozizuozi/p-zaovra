# 用量仪表盘

完成日期：2026-09-12。

## 入口与行为

- 新版输入框下方：本对话累计 Token、上一轮 Token、用量仪表盘入口。新对话显示 0，不继承其他对话的数字。
- 设置 → 用量仪表盘：自有 Key / 官方服务分别汇总输入、输出、推理、缓存读写和调用次数。
- 收到运行结算事件后，等待当前执行（包括工具续跑）结束再刷新。复用现有执行观察器，不新增模型请求或持续轮询。重新聚焦窗口时补同步。
- 加载失败明确提示并提供刷新；供应商未返回完整 usage 时标注统计不完整，已知 Token 显示为下限（≥）。
- 套餐已扣额度、剩余额度的入口在明细上方。尚无真实账户账单接口，因此显示“尚未接入账户数据”；不把 Token 或价格目录估算当成扣费。自有 Key 的供应商余额在供应商账户查看。

## 统计口径

- `/api/usage` 汇总当前服务器保留的 V2 运行事件；`sessionID` 参数限定当前对话。
- 对话栏统计当前对话的模型请求；独立子任务对话在总仪表盘中纳入汇总。对话栏悬停说明这一范围。
- “上一轮”按实际提升为可见消息的用户输入事件分组。模型的 inputSequence 会随工具续跑推进，不能直接用它分轮。
- 缓存与推理采用互不重叠的 Token 分项。自动/手动上下文压缩的模型消耗也记录；纯本地任务转交不计成模型调用。
- 使用持久化结算事件，避免对话翻页、撤回、删除或复制的展示消息改变累计消耗。查询不加载提示词、附件或压缩正文。
- 不包含其他应用、其他服务器的调用，也无法补出供应商未返回或历史上未记录的数据。费用与账户额度不属于本地 Token 账本。

## 验证

- Core：13 项测试通过，覆盖连续工具调用、真实用户轮次、来源拆分、重复结算、缺失 usage、压缩消耗和 SQLite 读取。
- HTTP：本地测试模型完成两轮对话、四次真实协议请求（包含 glob 工具续跑）。每轮 430 Tokens，累计 860；缓存与推理分项、删除后总量保留均通过。没有调用付费服务。
- 生产构建浏览器：两个测试通过，覆盖输入框入口、设置页签、等待执行结束再同步、失败重试、小窗口显示。
- Core / Server / app-ui / desktop-app 类型检查通过；新版客户端与 JavaScript SDK 已重新生成；桌面构建通过。
- 导航单次观测：修改前 206 ms，最终 229 ms。这是单次样本，不作为统计意义上的性能结论。
