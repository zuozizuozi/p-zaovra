# 附件能力实施记录

目标：在现有桌面新对话中拖入文件，获得可读的解析状态与结果；使用现有会话协议传递解析内容，不制造只显示文件名的假支持。

## 社区方案核对（2026-09-12）

- Microsoft MarkItDown：MIT，Python >=3.10，普通 DOCX/XLSX/PPTX/PDF 转 Markdown；原生 ZIP 转换会忽略不支持的成员，因此由 Zaovra 在调用前检查成员、总展开大小、路径和嵌套，并报告未解析文件。https://github.com/microsoft/markitdown
- Docling：MIT 主代码，模型许可证单独核对；复杂文档使用 OCR/布局管线，音视频有 ASR/关键帧管线；安装和模型下载较重，不能让一次普通文件上传隐式下载整套模型。https://github.com/docling-project/docling
- Whisper：MIT 代码和模型；可用于本地音轨转录。https://github.com/openai/whisper
- FFmpeg：用于本地媒体解码/抽帧，分发时按实际构建核对 LGPL/GPL。https://ffmpeg.org/legal.html
- 不复制 Anthropic source-available 文档 skills。采用开源解析器和自有薄接入层；Skill 可补充分析流程，不能替代附件读取。

## 两阶段

1. 普通文档：MarkItDown + 有边界的 ZIP 检查。文件选择/拖拽/粘贴共用流程；后台转换；显示处理、失败、重试；解析中禁止提前发送。保留原文件名，结果作为文本附件经现有会话协议送达。
2. 复杂文档与音视频：按需安装高级解析运行环境。明确区分文档文本提取、OCR、音轨转录和关键帧，不把转录结果宣称为完整视频理解。超时/不支持/缺依赖需要可读错误，不静默忽略。

运行环境必须属于 Zaovra，不能依赖开发者 Codex 私有运行时路径。开发验证可用现有 Python 创建项目专用虚拟环境；应用通过固定项目/资源位置查找该环境。不得修改全局 Python 包。原始附件仅在本地临时目录处理。

## 实施与验证结果

两阶段均已实现于桌面 V2 输入框，通过现有文本/图片附件协议发送。前端选择、拖入、粘贴进入同一转换入口；解析任务排队，处理或失败未解决时阻止发送，提供重试与移除，移除会取消后台转换，跨会话与卸载后的结果不会回填。解析正文可点击预览。

本机项目专用 Python 与基础解释器均位于 `.cache/attachment-python*`，已安装文档/OCR/转录模型。无需使用 Codex 私有 Python 路径。继续使用仓库根目录 `启动造物.bat`；另有 `安装附件组件.bat` 供组件修复/重新安装。

验证通过：
- 10 项桌面真实文件转换测试：DOCX、XLSX、PPTX、ZIP、不安全 ZIP、格式/大小校验、真实语音转录、扫描 PDF、短且无音轨视频、取消信号。
- 4 项输入框生命周期测试：处理状态、移除与迟到结果、跨会话多文件批次、失败重试不重复。
- 14 项请求附件构建测试和 7 项后端模型消息转换测试通过，其中包含文本附件解码为模型正文。
- app-ui、session-ui、desktop-app 类型检查通过，桌面代码构建通过（未制作安装包）。

验证缺口：当前桌面 CDP 自动化连接超时，未完成运行中桌面的视觉/原生点击验收；未连接用户官方 API 进行真实付费模型调用。本轮没有新的生产导航性能基线，不能声称已完成此次性能对比。需在下次手动启动后人工确认拖入、解析状态、预览关闭和发送体验。

能力边界：每批原始附件 20 MB；解析文本最多 20 万字符；PDF 最多 100 页；媒体最多 15 分钟；视频均匀抽样最多 8 帧，不能视为逐帧完整理解。Office 图片/图表视觉内容需另加截图，Excel 不重算公式；ZIP 内 PDF 当前仅提取文字层，扫描 PDF 应单独添加。详细安装和格式说明见 packages/desktop-app/resources/attachments/README.md。
